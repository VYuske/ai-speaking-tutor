## Measurement notes

- TTFB is the time from the HTTP request to the first SSE chunk with non-empty `delta.content`; total is the time until the stream closes.
- Cold vs warm: every request repeats the same instruction prefix with a different café item, so the first run of a language is **cold** and later runs are **warm**. The server's prompt-prefix cache (Ollama reports it as `prompt_tokens_details.cached_tokens`) can skip re-prefilling the shared prefix, which is what makes warm TTFB lower than cold TTFB. One warm-up run per language runs first and is discarded: it pays the model load into VRAM (seconds on a CPU-first host) and the first prefix fill, so cold run 1 does not carry the model-load cost. If the server reports no cache reuse below, cold/warm differences here are run-to-run noise, not a caching effect.
- Server-reported prefix cache (`prompt_tokens_details.cached_tokens`): cold run 1 = 41 tokens, warm runs = up to 46.
- Cold TTFB is a single sample (run 1) — treat it as indicative, not a median.
- tokens/s = tokens divided by the generation window (`total_ms - ttfb_ms`). 12/12 successful measured runs used the server's `usage.completion_tokens` from the final `stream_options.include_usage` chunk; every measured run here is a server token count.
- Token estimate: whitespace-split words for `en`/`de`; for `ja`/`zh` characters/1.7 (CJK tokenizers emit roughly 1.7 characters per token — an approximation, not a tokenizer count).
- Each run is bounded by a 60 s socket timeout **and** a 90 s wall-clock deadline, so a server dribbling bytes cannot hang the benchmark; the socket timeout still bounds a single stalled read.
- Adherence is a heuristic: `ja` needs hiragana/katakana, `zh` needs CJK without kana, `de` needs ä/ö/ü/ß or two German stopwords, `en` needs ≥90% ASCII without CJK.
